# EzConn

Новый сервисный клиент для Kaparossa: C++20, Qt 6 Widgets, CMake/MinGW UCRT64.
На машине установлена RTOS-32; доступа для установки своего агента нет.
Работаем через существующий протокол, без изменений на стороне машины.
Стартовые требования: [EasyConn_Codex_Start.md](EasyConn_Codex_Start.md).

Первый исследовательский этап выполнен:
[протокол и API оригинала](docs/legacy_api.md).
Создан каркас EasyConnCore, Qt Widgets GUI и EasyConnProbe.
Адрес нового приложения по умолчанию: **192.168.1.66:2000**.
Реализованы отдельный LegacyHost (C#/.NET Framework) и минимальный протокол
чтения версий. Основное приложение и обмен с устройством остаются на C++.

## Экран и трансляция

Постоянная папка запуска — `dist\EzConn-video-fix`; скрипт Deploy-Windows.ps1
обновляет её на месте. Перед упаковкой закройте приложение. Каталог CMake — `build`.
Новые каталоги для каждой версии не создаются.

Single frame продолжает polling после промежуточного ответа команды 67,
до первого изображения (ожидание готовности — до 15 секунд). Для дельта-кадров
используется размер уже полученного экрана: Hscreen/Vscreen в обновлении могут
содержать размер участка. Исправление проверено на девяти сохранённых кадрах машины.

Декодер совместим с нулевыми RLE-повторами C0 оригинального клиента.
При ошибке декодирования полученный кадр сохраняется в
`%LOCALAPPDATA%\EzConn\diagnostics`; точный путь и заголовок выводятся в журнал.
Полностью полученный, но не декодированный кадр не разрывает соединение.
Окно экрана остаётся открытым при ошибке. RX-вывод ограничен первыми 128 байтами
каждого фрагмента с указанием полного размера; данные декодера не обрезаются.

После Connect → Read versions нажмите **Screen / Video**.
**Single frame** запрашивает полный кадр, **Start video** запускает обновления,
**Stop** прекращает их. Закрытие окна экрана также останавливает запросы.
Во время трансляции чтение каталогов и диска блокируется. При фокусе окна видео
физическая клавиатура передаёт F1–F12, Home, стрелки, Enter, Delete, цифры 0–9
и буквы A–Z (VK uppercase; цифры/Enter цифрового блока также поддержаны).
Нажмите Start video и оставьте окно видео активным; щелчок по изображению возвращает фокус.
Удержание клавиши не повторяет команду; сочетания с Shift/Ctrl/Alt/Win не передаются.
Левый клик по изображению передаёт touch; пустые поля и другие кнопки мыши игнорируются.
`ScreenView::framebufferPoint` пересчитывает позицию относительно `imageRect()` в
координаты исходного framebuffer, учитывая масштаб и поля; результат ограничен размером кадра.
Изображение автоматически вписывается в область
просмотра с сохранением пропорций, без обрезки и прокрутки. Размер пересчитывается
при изменении окна; свободные поля чёрные. Масштабируется всегда исходный кадр.

Клавиши и touch помещаются в общую FIFO-очередь (до 32 событий). Между завершёнными циклами
получения кадров отправляется одна команда 66; после её ответа запрашивается следующий
кадр. Клик обрабатывается сразу по текущему изображению независимо от FPS, но отправка
ждёт окончания текущего обмена. `RemoteKey::fromQt` возвращает optional VK;
`keyboardPacket` формирует `00 00 00 00 VK 00` для управляющих клавиш и букв.
Цифры отправляются как символы в последнем байте, как в оригинальном EasyConn:
например, `5` → `00 00 00 00 00 35`. `touchPacket` формирует `Xlo Xhi Ylo Yhi 00 00`.
Журнал содержит `KEY TX/RX` для клавиш и `TOUCH TX/RX` для координат.
Stop, ошибка или отключение очищают очередь. При потере ответа команда не повторяется.

Одиночный кадр использует команду 67 с reset=1 (тот же механизм, что видео),
а не файловую команду screenshot 70. Последующие обновления: reset=0.
Реализован PCX 24-bit RGB/RLE с наложением изменений. Передача запрашивается
только блоками по 250 KiB, в режиме compression + turbo. При чтении версии
всегда запрашивается маска 0x31. Переключателей, режима 62 KiB и несжатого
видеорежима нет; ScreenService принимает X и распаковывает собранный zlib-файл.
Общие типы пакетов для других сервисов протокола сохранены.
На формирование обновления отведено
30 секунд; каждые 5 секунд ожидания показывается статус. Блок допускает до
15 секунд без новых данных и до 60 секунд на передачу целиком. Повторных запросов
поверх незавершённого нет. После кадра следующий запрос идёт без искусственной
паузы; после ответа без обновления остаётся пауза 100 мс.
Во время видео отключён вывод сетевых пакетов, состояние и ошибки видны.
Статистика FPS усредняется с момента Start; capture/wait включает ожидание обновления,
transfer — все блоки, decode/display — распаковку PCX и передачу изображения в GUI
(без гарантии включения фактической отрисовки). Размер в KiB — до распаковки файла. Строка Video появляется
в журнале на первом и каждом десятом кадре. Измеряйте при сопоставимых изменениях экрана.
Видео и устойчивые тайм-ауты подтверждены пользователем; ускорения проверены локально.

## Чтение версий

В GUI нажмите Connect, затем Read versions. Результат появится в журнале.
Для повторной проверки отключитесь и подключитесь снова.

```powershell
.\dist\EzConn-video-fix\EasyConnProbe.exe --versions --tcp 192.168.1.66:2000
```

Последовательность TCP: аутентификация 1/2, версия ПО 14, опции 38, версия
протокола 3. COM пропускает аутентификацию. Тайм-аут каждого ответа — 5 секунд;
автоматических повторов нет. Команды записи/перезагрузки не отправляются.
Без --versions Probe сохраняет режим простого наблюдения транспорта.
Подтверждено на машине пользователя: MultiAssembler 4.3.16, protocol 3, options 0x22.

После чтения версий доступны **List directory** и **Disk information**.
Введите абсолютный путь с завершающим `\`, например `D:\`, и нажмите List directory.
Двойной щелчок по каталогу открывает его; `..` поднимает на уровень выше.
Disk information читает корень диска из указанного пути и показывает серийный
номер, размер кластера, общий/свободный объём и число повреждённых кластеров.
Имена отображаются без изменения регистра. Запросы выполняются по одному.
Новые функции проверены на имитаторе; реальная проверка каталога/диска ещё предстоит.

## Scanner Emulator (Rotor108)

После Connect → Read versions откройте **Scanner Emulator**. Перед отправкой
остановите видео и дождитесь завершения чтения диска. Окно содержит ASCII / RAW HEX,
поле BVBS, три пресета реальных изделий, Append CR/LF (включён), Send и Clear.
Пресеты только заполняют поле; для передачи нажмите Send.

Используется существующая авторизованная MachineSession и command 9, без COM/UART.
`ScannerService::sendScannerPayload` отправляет подготовленные байты одним P-пакетом.
Лимит его payload — 251 байт, включая CR/LF; превышение и пустой ввод отклоняются.
Размер mailbox Rotor108 из исходников клиента неизвестен; более крупные типы пакетов
для этой команды не используются, автоматического дробления нет.

ASCII допускает только ASCII и нормализует переводы строк в CR/LF. RAW HEX принимает
пары hex-цифр с необязательными пробелами, сохраняет любые байты и отклоняет неверный hex.
Append CR/LF добавляет реальные `0D 0A`, если их ещё нет в конце. Для Preset 2 конец
payload: `40 43 37 35 40 0D 0A`. Для точной передачи RAW HEX без добавлений снимите флажок.

Журнал показывает команду, длину, printable и hex payload, а также ответ/ошибку.
Пустой SendAnswer подтверждает приём команды, но не успешный ParsingBVBS/добавление изделия.
При E_NAME=3 выводится: "This Rotor108 firmware does not support Scanner RX Inject (command 9)."
Тайм-аут разрывает соединение без повторной отправки, чтобы не продублировать изделие.

## Сборка приложения

Рабочая среда: MSYS2 UCRT64 в `C:\msys64\ucrt64`, CMake, Ninja, MinGW,
Qt 6 (Core, Network, Widgets, SerialPort, Test), zlib. Пресет `ucrt64-release`
использует единственную папку `build`. Пути к инструментам заданы в проекте,
изменять системный PATH или открывать Developer PowerShell не требуется.

В VS Code откройте папку EzConnApp. После изменения настроек выполните
**Developer: Reload Window**. **Ctrl+Shift+B → EzConn: Build and deploy**
собирает проект и обновляет `dist\EzConn-video-fix` вместе с DLL.
Перед обновлением закройте запущенный EasyConn.exe.
Для кнопки Build расширения CMake Tools выберите Configure Preset
**ucrt64-release**; эта кнопка только собирает файлы в `build`, без упаковки в `dist`.

То же из обычного PowerShell в папке проекта (с тестами):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build-Windows.ps1 -Test -Deploy
```

Без `-Test` сборка пропускает запуск тестов; без `-Deploy` не обновляет `dist`.
Для отдельной упаковки уже собранных файлов:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Deploy-Windows.ps1
```

После этого запускайте `dist\EzConn-video-fix\EasyConn.exe` двойным щелчком.
Переносить нужно всю папку EzConn вместе с DLL и подпапками плагинов.
Скрипт запускает windeployqt и рекурсивно добавляет сторонние DLL MSYS2;
системный PATH не изменяется. Повторяйте упаковку после пересборки.
Скрипт рассчитан на текущий MinGW/UCRT64 toolchain; MSVC потребует соответствующего Qt.

Локальная сборка MinGW в установленной среде MSYS2 UCRT64:

```powershell
$env:PATH = 'C:\msys64\ucrt64\bin;' + $env:PATH
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
ctest --test-dir build --output-on-failure
.\build\EasyConnProbe.exe --tcp 192.168.1.66:2000
.\build\EasyConn.exe
```

Probe без аргументов использует 192.168.1.66:2000. Ждёт соединения до 5 секунд,
затем принимает данные 5 секунд и отключается. Время наблюдения меняется через
`--duration 10000`. COM: `--serial COM3 --baud 115200` (скорость здесь лишь пример,
её нужно выбрать по оборудованию). Exit codes: 0 — наблюдение завершено,
1 — ошибка/обрыв связи, 2 — неверные аргументы.

GUI поддерживает TCP; COM доступен через Probe. Общая MachineSession пишет UTC timestamps и hex
RX/TX-QUEUED: последнее означает принятие данных буфером Qt, а не подтверждение
доставки устройством. Асинхронные транспорты используют
[QTcpSocket](https://doc.qt.io/qt-6/qabstractsocket.html) и
[QSerialPort](https://doc.qt.io/qt-6/qserialport.html).

Исходный config в LegacyApp и исследование исторического адреса оригинала
сохранены как эталон. Для нового клиента используется отдельная константа
DefaultHost/DefaultPort в src/core/Connection.h.

## Воспроизведение проверки

Из корня репозитория в Windows PowerShell 5.1:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Inspect-Legacy.ps1
```

Проверка работает офлайн с исходными DLL в LegacyApp/EasyConn и записывает
результаты в artifacts/legacy. Не подключается к оборудованию.

Для повторной декомпиляции нужен .NET SDK 8:

```powershell
dotnet tool install ilspycmd --tool-path .tools --version 9.1.0.7988
.\.tools\ilspycmd.exe LegacyApp\EasyConn\Lib\TeleAssistenza.dll -o artifacts\legacy\TeleAssistenza
.\.tools\ilspycmd.exe LegacyApp\EasyConn\EasyConn.exe -o artifacts\legacy\EasyConn
.\.tools\ilspycmd.exe LegacyApp\EasyConn\Lib\Tool.dll -o artifacts\legacy\Tool
```

Оригинальные бинарники служат эталоном совместимости и не редактируются.
Локальные инструменты и декомпилированные файлы исключены из Git.

## LegacyHost

Собирается CMake в build/legacy через scripts/Build-LegacyHost.ps1. Нужен
.NET Framework 4.x с компилятором csc.exe. Использован минимальный C# host,
чтобы не связывать Qt/MinGW с C++/CLI; GUI не загружает .NET DLL.
Host служит эталоном для тестов C++ codec, не участвует в сетевом обмене.
IPC — stdin/stdout дочернего процесса, строковый ASCII-протокол; диагностика
идёт в stderr. Один запрос даёт одну строку `OK ...` или `ERR ...`.
Проверенный режим QProcess: передать пакет строк, закрыть stdin, получить ответы
до завершения процесса. Последовательные интерактивные запросы через QProcess
в текущей сборке Qt зависают после первого ответа; этот режим пока не используется.

```text
hello
encode 80 3 87 -
parse 50044241035753
auth 12345678
```

encode: decimal тип/команда/тип сообщения и hex payload (`-` для пустого).
parse возвращает decimal тип/получатель/отправитель/команда/тип сообщения и
hex payload. Host вызывает оригинальные formatoComando и codifica.
Граница payload — 1 MiB, для P — 251 байт, для C/T — 65531.
Z/H (сжатые пакеты) пока явно отвергаются. При запросе версий сжатие отключено.
Полный набор допустимых типов сообщения ответа ещё требует проверки на машине;
сейчас проверяются адреса, ожидаемая команда, размер, LRC и признак ошибки E.
